## 已确认的源码缺陷与修复

1. SessionManager 的单例每次访问都会再次调用初始化，重建 Session、丢失服务器更新的 Cookie。现仅初始化一次，锁住会话请求及 Cookie 更新。
2. get_job_list 将 HTTP 失败变为空列表，process_chapter 随后当成成功。现 403 抛出明确异常，章节标记 BLOCKED，无章节重试，记录失败；总任务有失败时退出码为 1，不发“全部完成”通知。
3. 未识别 HTML 不再当空任务。“暂无内容”使用网页观察到的官方空页面标志；空页面处理返回失败也不算成功。卡片 JSON 解析兼容等号周围空格，保留 JSON 字符串中的空格。
4. Cookie 支持旧文本、`Cookie:` 前缀、UTF-8 BOM 和值里的等号。保存为保留 domain/path/secure/expires/域标记的 JSON，排除过期项，原子替换，文件权限 0600；读取错误不再静默吞掉。旧文本无法还原原始域路径，导入时限定 `.chaoxing.com`。
5. Cookie 验证复用真实 Session，检查明确登录页面及登录重定向。普通网络错误和 403 不再直接推断 Cookie 已过期；移除任意 `login` 字样即失效的误判。重复身份 Cookie 值冲突明确停止。
6. Cookie 登录不自动退回账号密码登录。用户报告账号密码登录会循环重定向；此现象未在服务器复现，也不能声称已修好服务端认证。密码登录请求不自动跟随跳转，遇 3xx 或非 JSON 明确提示使用 Cookie；其他会话最多 5 次重定向。
7. 默认连接/读取超时 5/20 秒。共享 HTTP 适配器总计最多 2 次传输重试，仅 GET/HEAD 的读重试，连接错误可能在请求发送前重试；不做 HTTP 状态重试，不重放 POST 读取失败。章节网络失败最多 5 次尝试，403、其他 4xx、会话失效和格式错误停止重试。
8. 移除运行流程中的自动验证码识别/提交、403 后切换参数和刷新会话重试；碰到验证或拒绝访问时停止当前任务。OCR 不再是默认依赖。
9. 删除 Cookie、通知地址、原始页面、令牌日志。移除题库 Token 尾号日志，恢复题库请求 TLS 验证并补齐直接请求超时。日志 URL/常见凭据字段脱敏；默认 INFO，禁用局部变量诊断，单文件 5MB，保留 3 份。外部通知不发送堆栈；通知请求增加超时。
10. 非交互模式缺配置、课程列表或大模型连接失败时明确退出，不再 EOFError；课程 ID 未匹配不会意外运行全部课程。配置支持百分号和 BOM。
11. Docker 固定 `python:3.13-slim-trixie`（Debian 13），依赖独立层和版本锁文件，非 root 用户、只读根文件系统、权限收紧。
12. Compose 独立项目和默认桥接网络，不开放端口，不依赖宿主 MySQL/Redis/Nginx，不挂载 Docker socket。限制 CPU 0.5 核、内存与含交换的总上限 512MB、PID 64、临时目录 64MB，禁用自动重启，避免失败循环。建议 jobs=1。

## 更新已有部署

先确认 origin 指向自己的 Fork，工作区没有需保留的已跟踪改动。原配置/Cookie 不要提交到 Git，不要在终端打印出来。

```bash
cd /opt/docker/projects/chaoxing
git remote get-url origin
git status --short
git pull --ff-only origin main
mkdir -p config logs
# 仅首次创建；不会覆盖已有配置
[ -f config/config.ini ] || cp config_template.ini config/config.ini
```

用本地编辑器修改 `config/config.ini` 的 `[common]`：

```ini
use_cookies = true
username =
password =
course_list = 你的实际课程ID,另一个课程ID
jobs = 1
speed = 1
add_learning_count = false
work_redo_enabled = false
```

题库设置按原配置迁移；不需要 AI 时不要启用 AI provider。使用 AI 时先确认连接可用。

将自己官方浏览器中复制的 Cookie 请求头内容写入 `config/cookies.txt`。支持 `name=value; name=value` 或 `Cookie: name=value; ...`。不要把 Cookie 发到聊天或 GitHub。不要把 `Set-Cookie` 响应头当成请求头导入。若原文件在别的目录，私下复制到此处；不要覆盖已有有效 Cookie。运行后程序自动保存为 JSON，仍使用同一个文件名。

```bash
chown -R 10001:10001 config logs
chmod 700 config logs
chmod 600 config/config.ini config/cookies.txt
docker compose -p chaoxing config --quiet
docker compose -p chaoxing build --pull
docker compose -p chaoxing up -d --no-deps chaoxing
docker compose -p chaoxing logs --tail=100 -f chaoxing
```

可选阿里云 Python 镜像源（不关闭 TLS 验证）：

```bash
PIP_INDEX_URL=https://mirrors.aliyun.com/pypi/simple/ docker compose -p chaoxing build --pull
```

运行前如果以前有另一个容器正执行本项目，先识别并停止那个 chaoxing 容器，避免重复运行。不要停止 Java/MySQL/Redis/Nginx；不要运行 Docker 全局 prune、重启 Docker 服务或改系统防火墙/代理。

本程序执行一次后结束，`restart: "no"` 是有意设置。Cookie 更新后已停止的容器可重新启动：

```bash
docker compose -p chaoxing start chaoxing
```

若仍报 403：查看同一账号官方页面是否要求验证，手动处理后重新导入 Cookie。若平台继续拒绝 Python 客户端，保持失败状态，不自动破解或反复请求。
